## 1. Project Overview

### 1.1 The Problem
We chose to focus on group travel because travelling with multiple people often creates more challenges[cite: 3]. Different travellers may have different budgets, interests, schedules, and preferred travel paces, making it difficult to create a plan that works for everyone[cite: 3]. Unexpected changes such as bad weather, transportation delays, budget changes, or changing preferences can further disrupt the original itinerary[cite: 3].

Existing travel applications address some of these problems, but they often focus on specific parts of the travel experience[cite: 3]. For example, **Wanderlog** supports collaborative itinerary planning, budgeting, expense splitting, and travel organization, while **TripIt** focuses on consolidating bookings and managing travel itineraries[cite: 3]. However, existing solutions rarely bring group preference coordination, real-time adaptive planning, comprehensive traveller safety, and integrated expense tracking together into a single platform[cite: 3].

This creates an opportunity for **Plan&Go** to provide a more adaptive and integrated travel experience — helping groups make decisions together, automatically adjust plans when situations change, and providing additional safety support for women and other travellers[cite: 3].

### 1.2 The Solution
**Plan&Go** is an AI-powered travel companion designed to make group trips seamless, safe, and truly memorable[cite: 3]. Before you even set off, it takes the hassle out of preparation with smart packing lists and weather-matched outfit recommendations[cite: 3].

On the road, Plan&Go balances everyone’s budget, pace, and interests into a flexible itinerary that adapts automatically to unexpected changes like bad weather or transit delays[cite: 3]. More than just a logistics tool, it acts as an interactive travel journal with built-in safety support and smart expense sharing—keeping everyone protected while preserving your shared memories for years to come[cite: 3].

## 2. Ideation & Process (Evaluation Weightage: 25%)

### 2.1 Ideas We Considered

| Idea | Status | Why it was dropped / kept |
| :--- | :---: | :--- |
| **AI-Powered Smart Planning** | **Chosen** | This was selected as the main planning idea because it provides a personalised starting point for different types of travellers[cite: 3]. |
| **One-Click Adaptive Itinerary** | **Chosen** | We chose this idea because travel plans may change during a trip[cite: 3]. It makes the system more flexible instead of giving users only one fixed plan[cite: 3]. |
| **Weather-Aware Planning** | **Chosen** | We kept this idea because weather can affect outdoor activities and the overall travel experience[cite: 3]. |
| **Integrated Flight & Stay Booking** | **Chosen** | We selected this idea to reduce the need for users to switch between different platforms when arranging their trip[cite: 3]. |
| **In-App Share Wallet** | **Dropped** | We initially planned to include an e-wallet where travel partners could transfer and use their trip budget within the app[cite: 3]. However, implementing financial transactions within a short development period was not feasible[cite: 3]. We were also concerned about financial security, which we could not confidently guarantee with our current resources and skills[cite: 3]. Therefore, we decided to drop this feature[cite: 3]. |
| **Smart Expense Tracking** | **Chosen** | We chose this idea because managing group spending can be difficult, especially when several people share expenses[cite: 3]. |
| **AI Bill Splitting** | **Chosen** | We kept this idea because splitting expenses manually can be time-consuming and may cause mistakes or disagreements between travellers[cite: 3]. |
| **One-Tap Travel Guardian** | **Chosen** | We selected this idea because safety is a major concern when travelling, especially when users need help quickly during an emergency[cite: 3]. |
| **Live Location Navigation** | **Dropped** | We initially planned to use the traveller’s live location to suggest routes to their destinations, mainly through walking or public transportation such as buses[cite: 3]. For walking routes, the app would also display the traveller’s live location while they were travelling[cite: 3]. However, we decided to drop this idea because continuously collecting and displaying users’ real-time location could create privacy and security concerns[cite: 3]. It would also require more complex location services and real-time tracking, making it less feasible to implement reliably within our limited development time and resources[cite: 3]. |
| **Real-Time Public Transportation Tracker** | **Dropped** | We initially planned to provide real-time tracking for buses, MRT, and LRT, including estimated arrival times, future schedules, and notifications when a service was delayed or cancelled[cite: 3]. However, we decided to drop this idea because we did not have sufficient access to reliable and real-time public transportation data[cite: 3]. Accurate delay and cancellation information would require data from transportation operators or reliable real-time APIs, which were not readily available to us[cite: 3]. Without a consistent data source, the information shown by the app could be inaccurate and potentially cause users to miss their transportation[cite: 3]. Therefore, this feature was considered too difficult and unreliable to implement within our development time and resources[cite: 3]. |
| **Live Location Circle** | **Chosen** | We chose this idea because it helps travelling groups stay connected and makes it easier to know where group members are[cite: 3]. |
| **AI Travel Stylist** | **Chosen** | We kept this idea because choosing suitable clothes can be inconvenient when travellers need to consider different destinations and weather conditions[cite: 3]. |
| **Smart Packing List** | **Chosen** | This idea was selected because travellers may forget important items when preparing for a trip[cite: 3]. |
| **Travel Footprint** | **Chosen** | We kept this idea because it adds a personal and memorable aspect to the travel experience by allowing users to record their journey[cite: 3]. |
| **Daily Travel Journal** | **Chosen** | This idea was selected because it allows travellers to record their experiences and emotions instead of focusing only on practical trip planning[cite: 3]. |
| **Trip Harmony Score** | **Chosen** | We chose this idea because it provides a way for travellers to reflect on their overall group experience after the trip[cite: 3]. |

## 5. Technical Architecture & Feasibility

### 5.1 Tech Stack

| Category | Technology / Service | Purpose / Reason |
| :--- | :--- | :--- |
| **Frontend** | React + Vite<br>Tailwind CSS<br>Leaflet.js | Lightweight, fast-loading travel-planning interface with interactive itinerary mapping and component styling[cite: 3]. |
| **Backend** | Python + FastAPI<br>Docker | High-performance asynchronous API for AI orchestration, OCR pipeline, trip logic, and third-party integrations[cite: 3]. |
| **Database** | Supabase PostgreSQL | Stores user profiles, trips, itineraries, expenses and daily check-ins; provides free-tier database and authentication[cite: 3]. |
| **ExchangeRate API** | ExchangeRate-API | Real-time currency conversion for multi-currency expense tracking and budget calculations[cite: 3]. |
| **AI Services** | Gemini / OpenAI API | Personalised itinerary generation and AI-powered trip recaps[cite: 3]. |
| **Maps & Services** | Google Maps Platform | Maps, routes and nearby places[cite: 3]. |
| **OCR** | Google Cloud Vision / Gemini Vision | Extracts information from uploaded receipt[cite: 3]. |
| **Weather** | OpenWeather API | Provides weather information for trip planning and dynamic updates[cite: 3]. |
| **Hosting** | Vercel + Render / Railway | Simple public deployment suitable for a hackathon[cite: 3]. |

> **Technical Constraints & Mitigations:**  
> For the constraints, we expect free-tier API quotas, hosting cold starts, limited database resources and occasional AI/OCR inaccuracies[cite: 3]. API keys will be kept server-side rather than exposed in the frontend[cite: 3].
